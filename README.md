# Store

متجر رقمي باللغة العربية العراقية، مبني باستخدام Node.js وExpress وPostgreSQL، ومهيأ للنشر على Clever Cloud.

## الإصدار

الإصدار المستهدف حالياً هو `0.0.2`، وما زال قيد التحقق. رقم الإصدار لا يثبت اجتياز اختبارات PostgreSQL والأمان والنسخ الاحتياطي والاستعادة أو قبول الواجهة المنشورة. راجع [سجل التغييرات](CHANGELOG.md) و[قائمة التحقق للإصدار](RELEASE_CHECKLIST.md). راجع [سجل التغييرات](CHANGELOG.md) و[قائمة التحقق للإصدار](RELEASE_CHECKLIST.md).

## التشغيل

```bash
npm install
npm start
```

لفحص صياغة ملفات JavaScript المتضمنة في سكربت التحقق الحالي:

```bash
npm run check
```

هذا الفحص لا يغني عن اختبارات API أو اختبارات القبول على بيئة النشر.

## متغيرات البيئة

- `PORT`: يحددها Clever Cloud تلقائياً.
- `POSTGRESQL_ADDON_URI`: رابط اتصال PostgreSQL المقدم من Clever Cloud.
- `STORE_NAME`: اسم المتجر (الافتراضي `Store`).
- `STORE_LOGO`: مسار الشعار (الافتراضي `/Logo.png`).
- `STORE_LINK`: الرابط العام للمتجر.
- `ADMIN_USERNAME`: اسم مستخدم لوحة الإدارة.
- `ADMIN_PASSWORD`: كلمة مرور قوية للوحة الإدارة؛ لا تضعها في ملفات المستودع.
- `ADMIN_LINK`: مسار سري يبدأ بـ `/` ويحتوي على 12 حرفاً أو أكثر، مثل المسار الذي أعددته في Clever Cloud.

عند التشغيل ينشئ التطبيق جداول قاعدة البيانات المطلوبة تلقائياً إذا كان الاتصال متاحاً.

## لوحة الإدارة والمشاركات

تُفتح لوحة الإدارة من المسار المحدد في `ADMIN_LINK` فقط. سجّل الدخول باستخدام `ADMIN_USERNAME` و`ADMIN_PASSWORD`. تُحفظ المشاركات في PostgreSQL، وتظهر للزوار فقط عند اختيار حالة «منشورة». استخدم كلمة مرور طويلة وفريدة ولا تشارك المسار السري أو بيانات الدخول. جلسات الإدارة محفوظة في PostgreSQL وتنتهي بعد 8 ساعات، ومحاولات الدخول محدودة مؤقتاً في قاعدة البيانات لدعم تعدد نسخ الخادم.

## نطاق الإصدار الأولي

الوظائف الموجودة في الشيفرة تشمل عرض المنتجات المنشورة والأقسام والبحث، وتفاصيل المنتجات والتنزيل، وعرض المشاركات المنشورة، وإدارة المشاركات والمنتجات والأقسام من لوحة الإدارة. أضيفت اختبارات HTTP smoke آلية لوضع التشغيل دون قاعدة بيانات، لكنها لا تستبدل اختبار PostgreSQL الفعلي أو فحص واجهة الإنتاج. راجع قائمة التحقق قبل النشر.


## اختبارات الإصدار 0.0.2

تشمل `npm test` اختبارات أدوات slug وHTTP smoke. عند توفير `TEST_DATABASE_URL` أو `POSTGRESQL_ADDON_URI` تُشغّل أيضاً اختبارات تكامل PostgreSQL. يوفّر GitHub Actions قاعدة PostgreSQL مؤقتة للاختبارات ولا يستخدم بيانات الإنتاج. لا تُعد هذه الاختبارات بديلاً عن تجربة النسخ الاحتياطي والاستعادة أو فحص الواجهة في متصفح حقيقي.

## النسخ الاحتياطي والاستعادة (الإصدار 0.0.2)

يتطلب تنفيذ الأوامر تثبيت أدوات PostgreSQL (`pg_dump` و`pg_restore`) على جهاز المشغّل، وعدم تخزين رابط قاعدة البيانات في المستودع.

- أنشئ نسخة: عيّن `POSTGRESQL_ADDON_URI` أو `TEST_DATABASE_URL` ثم شغّل `node scripts/backup-db.js`. يمكن تحديد المسار عبر `STORE_BACKUP_PATH`.
- استعادة إلى قاعدة منفصلة فقط: عيّن `STORE_RESTORE_DATABASE_URL` إلى قاعدة مستهدفة منفصلة، ثم `RESTORE_CONFIRM=RESTORE_TO_TEST_DATABASE`، وشغّل `node scripts/restore-db.js /path/to/backup.dump`.
- أمر الاستعادة قد يستبدل جداول موجودة في قاعدة الهدف. تحقّق من عنوان الهدف وخذ نسخة احتياطية منه قبل المتابعة. لا تستخدم قاعدة الإنتاج هدفاً للاستعادة التجريبية.
- ملفات النسخ المحلية مستثناة في `.gitignore`؛ احتفظ بنسخ مشفرة خارج المستودع وجرّب الاستعادة دورياً.
